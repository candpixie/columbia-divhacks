# Design: What's the Catch

Generated by /office-hours, 2026-09-26 ~4pm (judging Sun 12pm, Devpost due Sun 10:30am)
Status: APPROVED direction (A). Builds on Rent Radius; does not replace it.
Mode: Builder (hackathon). Track: Hack the City.

## Why we changed

A judge saw the map and said "not groundbreaking." They never saw the group-chat agent. The team's
strongest instinct in brainstorming: *"Apartment apps tell you which apartments, but they don't tell you the
shady part. Why is that apartment so cheap?"*

## Problem

Every NYC renter asks "what's the catch?" and no listing app answers it. The answers are public but scattered:
no-heat complaints, housing code violations, bedbugs, evictions, who really owns the building, whether units
are rent-stabilized. You find out after you've signed.

**Hook:** In Hong Kong you can look up whether someone died in a flat (凶宅 listings). In New York you can't
easily find out whether the heat worked last winter.

## What we build

**Paste an address or listing (site or group chat) → "The Catch" report card for that building.**

| Signal | Source | Status |
|---|---|---|
| Rent-stabilized units | nycdb rentstab (Alina, `scripts/justfix`) | built |
| Open HPD violations | nycdb hpd_violations (Alina) | built |
| Good Cause Eviction likely covered | Alina's flag | built |
| Real owner / portfolio | Who Owns What deep link (`justfix.ts`) | built (link) |
| No heat / hot water complaints, last 2 winters | 311 `erm2-nwe9`, by BBL | new |
| Bedbug reports | `wz6d-d3jb`, by BBL | new |
| Evictions | `6z8x-wfk4`, by BBL | new |
| Neighborhood context | existing 23 layers + rent trend (Tiger) | built |

Address → BBL via NYC GeoSearch (`geosearch.planninglabs.nyc`, no key). Verified: "125 white st" → BBL 1001670001.

Output: a short verdict ("3 red flags") plus the evidence, each line sourced and dated. The tone is honest, not
scary: "12 no-heat complaints last winter (city median for similar buildings: 2)."

## Where it shows up

1. **Website:** address box on top of the map; the report card opens in the side panel.
2. **Group chat agent:** anyone pastes an address or listing link → bot replies with the catch + card link.
   This is the Photon hero moment: the agent protects the group before they sign.

## Premises

1. Facts only, every line cites dataset + date. No AI-written facts; Gemini may summarize, with the same numeric check as the referee.
2. No crime or demographics in the building card (redlining risk). Building conditions only.
3. Compare to a baseline (median for the neighborhood / building size), otherwise raw counts mislead.
4. Keep what works: map, True Cost, Tiger, agent. The pitch leads with the chat, then the card, then the map.

## Build order (tonight)

1. `/api/catch?address=` : GeoSearch → BBL → parallel Socrata queries (311 heat, bedbugs, evictions) + Alina's building data. Cache results.
2. Report card component (Alina's data + new signals + JustFix links).
3. Agent: detect an address in the group chat → catch summary + link.
4. Demo: 3 prepared addresses (one clean, one with red flags, one rent-stabilized) checked by hand beforehand.
5. Deck + Devpost update: lead with "What's the catch?"

## Success criteria

- 3 demo addresses return correct, hand-verified cards in < 3 seconds.
- Agent answers an address pasted in a real group chat.
- Every number on screen traces to a named public dataset.

## Out of scope

Deaths / "haunted" data (NYC has no public registry; say so in the pitch as the gap we're closing on the rest),
scraping listing sites, landlord ratings/reviews.

## The Assignment

Before building: pick the 3 demo addresses tonight. One should be a building someone on the team actually lived
in or toured. A real story on stage beats any feature.
